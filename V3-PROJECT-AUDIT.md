## 4. Proposed database changes — **none made in Part 1**

1. **First:** inspect a sanitized production schema/migration ledger and role assignments; compare with `0001`–`0013`, back up and rehearse migration/rollback. Avoid changing old migrations or user/donation IDs.
2. **If grant management is approved and specified:** add forward-only migrations for grant programs, applicants, applications, eligibility answers, reviews/decisions, awards, milestones/disbursements, attachments and actor/event history; define unique keys, statuses, foreign keys, retention and monetary currency invariants. Do not create these tables without a requirements sign-off.
3. **If external settlement is approved:** model immutable bank import batches/statement lines, matching decisions and reviewer evidence/reversal history with unique external references and per-currency amounts; never overwrite existing transactions or mark legacy completed gifts verified automatically.
4. **For self-service, first reuse existing schema:** routes/views may be missing while donor/fundraiser/team tables already exist. Add columns/indexes only after tracing real query plans and confirming production data. Test migration replay/partial-DDL recovery.
5. Preserve V2 review, evidence, partial refund and gross/net rules; no cross-currency arithmetic or retroactive backfill without audited provenance.

## 5. External integrations and prerequisites to verify

- Meezan and Etisalat/UBL: merchant sandbox accounts, callback allowlists/signatures, inquiry and refund APIs, reconciliation statements, test cases with provider sign-off. No live tests performed.
- SMTP/PHPMailer: sender ownership, TLS, queued-job retry and bounce/receipt visibility; independent cron worker preferred.
- Separate fundraiser host/database: decide whether linked user journeys live there or locally; require interface/API ownership, read-only credentials if cross-DB statistics are desired, URL parity and deployment coordination.
- CAPTCHA, third-party embeds/maps, PHP extensions (`pdo_mysql`, `mbstring`, `openssl`, `curl`, `fileinfo`, `zip`, image library, `intl`), HTTPS proxy behavior, private storage outside public routing, reliable backups and legal tax documentation.

5. Implement specified grant workflows and migrations **only if authorized**, with security/retention and approval controls.
6. Stage bank/SMTP/fundraise integrations, run adversarial and accessibility checks, verify security headers/private uploads, document migration/rollback and obtain business/legal/provider approval before live enablement.
